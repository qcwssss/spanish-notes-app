# 分享按钮 UI 提案（Icon-Only）

## 目标
- 减少编辑器右上角拥挤感
- 保持关键操作直达
- 使用 icon 传达语义，减少文字按钮密度
- 风格更简洁、层级更清晰、学习成本更低

---

## 方案 A（推荐）

### 核心思路
- 顶部只保留 3 个 icon 操作位：编辑、分享、更多
- 不在顶部直接展开“复制链接 + 撤销分享”两个额外按钮
- 通过 `More (···)` 做渐进披露

### 顶部布局（ASCII）
```text
+------------------------------------------------------+
| Note Title                                  [✎] [↗] [⋯] |
+------------------------------------------------------+

[✎] 编辑
[↗] 分享（首次分享/已分享都只占一个位置）
[⋯] 更多操作（复制链接/撤销分享/删除）
```

### More 菜单（未分享）
```text
┌──────────────────────┐
| ↗  Share note        |
| ──────────────────── |
| 🗑  Delete note       |
└──────────────────────┘
```

### More 菜单（已分享）
```text
┌──────────────────────┐
| ⧉  Copy link         |
| ✕  Stop sharing      |
| ──────────────────── |
| 🗑  Delete note       |
└──────────────────────┘
```

### 为什么推荐
- 顶部密度稳定，不会因为“已分享状态”突然从 2 个变 4 个按钮
- 分享仍是一级入口（可直达）
- 删除/撤销等高风险操作下沉到二级，降低误触
- 更符合“简洁+层级明确”的高端产品体验

---

## 方案 B（备选）

### 核心思路
- 顶部只保留 `[✎] [⋯]`
- 分享相关全部进入更多菜单

### 布局（ASCII）
```text
+------------------------------------------------------+
| Note Title                                        [✎] [⋯] |
+------------------------------------------------------+
```

### 优缺点
- 优点：最简洁
- 缺点：分享要多一步，频繁分享场景效率略低

---

## 方案 C（不推荐）

### 核心思路
- 顶部所有动作都显示为 icon

### 布局（ASCII）
```text
+------------------------------------------------------+
| Note Title                           [✎][↗][⧉][✕][🗑] |
+------------------------------------------------------+
```

### 优缺点
- 优点：所有操作可见
- 缺点：最拥挤，视觉噪音高，不够克制

---

## 交互细节建议（适用于推荐方案 A）
- 桌面端：icon 悬停显示 tooltip（帮助首次学习）
- 移动端：触控热区至少 44x44
- 所有 icon 添加 `aria-label`
- 危险操作（删除/撤销）在菜单中使用警示色并和普通操作分组

---

## 结论
- 推荐实施 **方案 A**：`[✎] [↗] [⋯]`
- 在保持极简外观的同时，兼顾分享效率与误触控制
